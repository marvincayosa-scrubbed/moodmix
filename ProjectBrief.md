# Part 2: Course-Provided Instructions  
## Leave this section as written

## Preferred Technology

Use simple:

- HTML
- CSS
- JavaScript

Prefer a small number of files:

- `index.html`
- `style.css`
- `script.js`

The project should work in a browser.

---

## Technical Guardrails

Do not include:

- Login
- User accounts
- Passwords
- Payments
- Databases
- Backend servers
- External APIs
- Real client data
- Work data
- Confidential data
- Sensitive personal data
- Deployment requirements
- GitHub requirements
- Complex frameworks
- Package managers
- Build tools
- Analytics
- Tracking
- Admin panels
- Multi-user features
- Anything production-critical

If a requested feature seems to require one of these, suggest a simpler first-version alternative.

---

## How Codex Should Work

Before coding, Codex should:

1. Restate the project in plain English.
2. Identify the simplest useful first version.
3. List the files it plans to create.
4. Explain how to run or preview the project.
5. Explain how to test the main user flow.

Then Codex should build the simplest working version first.

After building, Codex should summarize what changed in plain English.
